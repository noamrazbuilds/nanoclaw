## Behavioral spec (one paragraph)
When a WhatsApp user adds or removes an emoji reaction on a message (Baileys `messages.reaction` event), the channel adapter resolves the chat JID (translating LID→phone if applicable), filters to registered groups, and writes the reaction to a `reactions` SQLite table with composite primary key `(message_id, message_chat_jid, reactor_jid)`. An empty emoji removes the row (`DELETE WHERE ...`); a non-empty emoji upserts (`INSERT OR REPLACE`). The agent can react outbound via the `react_to_message` MCP tool — emoji + optional `message_id` (omitting means "react to latest message in chat"); empty emoji removes the bot's reaction. The reactions surface is read by the agent through SQLite queries to power skills like `/add-reactions` (user-facing reaction sending) and the container `reactions` skill (agent reaction docs). The reason: emoji reactions are first-class lightweight signal in WhatsApp culture — both ways. Users react to indicate acknowledgment, agreement, emotion; the agent reciprocates to feel responsive without sending text.
