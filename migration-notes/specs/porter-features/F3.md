## Behavioral spec (one paragraph)
A container skill that listens for messages matching trigger patterns (`!listen <URL>` / `!read <URL>` / natural-language variants) and converts the article at the URL into an audio voice note. Pipeline: (1) extract article text via `extract.py` (newspaper3k or readability heuristics, ads/nav stripped), (2) chunk text by sentence boundary (TTS API has per-call length limits), (3) call TTS backend (OpenAI by default with `shimmer` voice; user-overridable to ElevenLabs or piper via inline syntax `use elevenlabs`), (4) concatenate audio chunks via `ffmpeg -f concat`, (5) optionally mix background audio (synthetic brown noise generated on the fly OR ambient file from `/ambient-audio/<bg-type>.{mp3,opus,wav}` — e.g. rain, ocean, forest-wind), (6) deliver via IPC as a voice note. The script enforces hard discipline ("MUST use the script — do NOT call TTS directly, do NOT implement your own pipeline") because the agent's natural tendency is to step through the pipeline manually, which loses chunking/mixing/delivery primitives. The reason: the user wants long-form web content (articles, blog posts) consumable as audio while doing other things; this is one of the more-used customization features (per [[project_link_to_audio]]).

## Decisions / open questions
1. **`packages_pip` schema extension** (the critical OQ): F3 is the first skill to need Python pip deps in v2. Options:
   - (a) Add `packages_pip TEXT NOT NULL DEFAULT '[]'` column to `container_configs` table via new migration. Mirrors the existing `packages_apt`/`packages_npm` pattern. Cleanest long-term, but requires schema change + container-runner support for pip install.
   - (b) Bake Python deps into the container image at build time via `container/Dockerfile`. No schema change but inflates image size for groups that don't use Python skills; also forces a container rebuild per skill addition.
   - (c) Include a `requirements.txt` in `container/skills/link-to-audio/` and let container startup do `pip install -r` if found. Per-skill, lazy, no schema change. Adds runtime startup cost.
   - **Recommend (a)** — symmetry with apt/npm, cleanest, sets precedent for future Python skills. Cost: one migration + container-runner pip-install step (small).
2. **Ambient audio files location**: where do they live in v2? Currently `/ambient-audio/<type>.opus` paths are hardcoded in `link2audio.py:31`. Options:
   - (a) Mount from a host directory via `additional_mounts` (current v1 pattern).
   - (b) Bundle inside the skill directory: `container/skills/link-to-audio/ambient-audio/` and update the script path constant.
   - **Recommend (b)** — self-contained skill, no separate mount config required, easier upstream-contribution-prep (Phase 5). Path constant change: `AMBIENT_AUDIO_DIR = os.path.join(os.path.dirname(__file__), '..', 'ambient-audio')`. Asset files need to be copied from v1 install (find them at current production mount).
3. **Per-group enablement default**: production currently has this in main groups only (telegram_main, whatsapp_main). Continue or open to all groups? Recommend match v1 — selective per `container_configs.skills` array. Don't default-enable.
4. **Backend availability defaults**: SKILL.md mentions piper backend; verify whether the piper binary is present in v2's container image. If not, document as "openai/elevenlabs only on v2 until piper is added to packages_apt".
