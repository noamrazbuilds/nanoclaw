  # Ensure OneCLI CA cert exists (extract from container if missing)
  if [ ! -f "$ONECLI_CA" ]; then
    log "CA cert missing — extracting from OneCLI container"
    docker compose -f "$HOME/.onecli/docker-compose.yml" exec -T app cat /app/data/gateway/ca.pem > "$ONECLI_CA" 2>/dev/null || true

## Behavioral spec (one paragraph)
Host-side scripts that make HTTPS calls through the OneCLI proxy need access to the proxy's CA certificate (`curl --cacert <ca.pem>`). The cert is generated by the OneCLI container and stored at `/app/data/gateway/ca.pem` inside it. On a fresh host install (or after a `data/` rebuild), the cert is missing from the host filesystem; the script's first check is "is the cert present at `data/onecli-proxy-ca.pem`?" If not, extract it from the running OneCLI Docker container via `docker compose exec -T app cat /app/data/gateway/ca.pem > $ONECLI_CA`. The block fails gracefully (`|| true` + `2>/dev/null`) — if OneCLI isn't running, the subsequent `curl --cacert` will fail with a useful error rather than this preamble killing the script. The reason this exists: without it, every host rebuild requires manual cert copy (`docker cp` or similar); the auto-extract is a five-line ergonomics fix that makes the script self-bootstrap. **Verifier-2 narrowing (2026-05-18): v2's container-runner + build.sh handle CA cert mount + bake-in NATIVELY for agent containers (SDK-internal). The fork's value-add is ONLY this host-side extract pattern for scripts running on the host outside of any container.**

## v2-native equivalent that might suffice?
**DOES-NOT-EXIST (host-side scripts).** v2's native cert handling (container-runner + build.sh) covers AGENT containers exclusively — runtime cert mount + image bake. The pattern fails for host-side scripts that aren't running inside a container (e.g., a cron job that uploads backups via the proxy). For those, the cert must be on the host filesystem; this block fills that gap. **Verifier-2 confirmed 2026-05-18.**
