## Behavioral spec (one paragraph)

When an inbound voice message arrives on any registered channel (WhatsApp `audioMessage.ptt=true` via Baileys, or Telegram `message:voice` via grammY), the channel adapter downloads the audio buffer and routes it through a channel-agnostic `transcribeAudioBuffer(buffer): Promise<string|null>` helper in v2 core. The helper tries local faster-whisper first (subprocess to `scripts/whisper_transcribe.py`, 60s timeout, `WHISPER_PYTHON` interpreter override allowed); on null/error it falls back to the OpenAI Whisper API (`whisper-1`, `response_format: 'text'`, key from `OPENAI_API_KEY` via `readEnvFile`); on full failure it returns the fixed string `[Voice Message - transcription unavailable]`. The transcript replaces the otherwise-empty message content before storage/routing so the agent receives voice notes as text. Reason: zero-cost path when local works, reliable fallback when it doesn't, unified surface across channels — voice notes are first-class user input.
