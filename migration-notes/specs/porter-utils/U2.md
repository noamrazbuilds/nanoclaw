## Behavioral spec (one paragraph)

When the WhatsApp adapter's `messages.upsert` handler receives a message carrying `imageMessage` (Baileys protobuf), it downloads the binary buffer via `downloadMediaMessage`, resizes through `sharp` (max 1024px, jpeg quality 85), writes the file under `<groupDir>/attachments/img-<ts>-<rand>.jpg`, and replaces the message content with `[Image: <relativePath>] <caption>`. For `stickerMessage`, it downloads the .webp buffer, converts to .png via `sharp().png()`, writes under `<groupDir>/attachments/sticker-<ts>-<rand>.png`, and replaces content with `[Sticker: <relativePath>]`. Downstream, `parseImageReferences()` extracts the markers and yields `{relativePath, mediaType}` pairs for the agent dispatch pipeline to read back as base64 multimodal vision content blocks. Reason: photos and stickers carry conversational meaning the agent must see directly — particularly stickers (per production data) which often ARE the message in family/EMS chats.
