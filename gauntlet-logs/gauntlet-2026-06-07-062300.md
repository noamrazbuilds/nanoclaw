- The agent runs INSIDE a per-session container via the Claude Agent SDK; the host (Node) spawns containers and communicates only via two SQLite files per session (inbound.db host→container, outbound.db container→host).

- v1 (prior system) detected credit-exhaustion text in the SDK result/stderr, swallowed the raw error from the user, notified the user ('...re-running on Gemini...'), and re-ran the SAME request EXACTLY ONCE in a FRESH isolated session (no session-resume — resuming bounces back to the same Anthropic model) on gemini-2.5-flash. - C1 must work for BOTH interactive messages and scheduled tasks (respecting suppress_chat_output for the notification).

THE DECISION — how does the one-shot fallback retry actually run on gemini in v2?
- A: Route the RETRY container through the user's LiteLLM by setting ANTHROPIC_BASE_URL + ANTHROPIC_AUTH_TOKEN (pointing at LiteLLM) + model='gemini-2.5-flash' on the respawned fallback container.
